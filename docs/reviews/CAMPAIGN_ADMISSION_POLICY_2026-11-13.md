No separate raw-ingress global circuit breaker is retained. edge-global now counts acknowledged, committed HTTP admission up to2000/SQL minute, after address240. Both reservations succeed in one transaction or neither persists. Enrollment similarly reserves new-address5 and new-global60 together; visitor120 is a single bounded admitted-attempt budget. Fixed-window burstiness remains. No migration/API/env/cookie/header/rule changes.

The DB supplies one minute timestamp per reservation, shared by every bucket even if execution spans a boundary. A conditional INSERT/ON CONFLICT UPDATE WHERE hits<limit returns no row on exhaustion. Logical refusal raises429 and rolls back the transaction. SQL/connectivity/lock failures return sanitized503 and never dispatch a request without acknowledged admission. Over-limit attempts do not increment/clamp overflow counts. Already admitted requests consume budget even if they later fail authentication/validation, miss a route, encounter downstream failure or retry an identical command. No refunds, fallback or automatic admission retries. Ambiguous COMMIT acknowledgement can conservatively spend quota without dispatch; retry charges another attempt and cannot assume rollback.

Lock order: address then corresponding global, immediate COMMIT, before any visitor/head or bootstrap lock. Visitor single-bucket reservation is separate. No mission evaluation, browser/network response work or external call occurs while budget locks are held. Waiters have250ms lock_timeout. Reserve-only idle_in_transaction_session_timeout3s releases a holder whose worker stalls between statements/COMMIT; existing statement_timeout3s remains. Checked-out PG clients have a temporary error listener; failed leases are discarded, so backend idle termination does not cause an unhandled process error. The listener is removed before release. No new record schema/table/function is required in production.

Raw HTTP floods still cost admission SQL/connections; this is not a network/DDoS firewall or a throughput guarantee. One abusive source no longer spends the shared admitted-work quota beyond its address allocation. Distributed sources, many serverless instances, IP normalization/provenance, provider connection caps, region latency, WAF fairness and rate limiting before the function require actual authorized staging. No upstream effectiveness is claimed or tested. Hosted resources/public loads remain prohibited in this task. No provider configuration changes.

Existing hashes/realm minute keys are retained. Use identical realm, abuse key and stable canonical trusted address across instances. Do not run mixed old/new workers: old workers can still cause original starvation; older above-cap rows conservatively deny until rollover. Same-host cookie and local operator restart rollback limits remain explicitly unchanged. Nothing mounts either factory. External Astra review and actual hosted staging remain release gates.
