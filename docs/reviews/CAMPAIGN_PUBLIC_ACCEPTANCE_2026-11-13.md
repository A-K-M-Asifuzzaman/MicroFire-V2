## Implemented public-user model

- Anonymous visitors receive a cryptographically random 32-byte session value only in a Secure/HttpOnly/SameSite=Strict `__Host-microfire_campaign_session` cookie, Path=/, no Domain. The server stores its namespace-specific SHA-256 digest, never its raw value. Campaign UUIDs are generated by the server and confer no authority.
- Each visitor has one authoritative campaign in managed PostgreSQL, bound to realm, protocol/rules, pinned origin, release epoch and catalog hash. No process-memory or /tmp production fallback exists. Different visitors cannot address or mutate each other's case.
- Every request checks exact origin/Host and Fetch Metadata plus the custom header; mutations require an origin-scoped session HMAC CSRF token. Bootstrap is the only guest enrollment path and requires exact-origin JSON/custom-header initiation. GETs return only the owning visitor's case. No CORS permission is granted.
- Mutations use one PostgreSQL client/transaction with visitor/head row locks, current expiry/revocation checks before commit, expected revision and canonical campaign identity. Exact accepted retries return the stored response; stale/conflicting edits return 409. The unchanged mission reducer derives progress and Passport updates.
- Public clients receive a strict projected view, not local CampaignSnapshot, raw records, injected faults, private grading hints or checkpoints. Diagnostic output is gated on use of the diagnostic tool; trial prompts omit expected answers/hints. User submissions and authorized educational feedback are distinct from private answer rubrics.
- Resume accepts only an empty object and reads the current durable head. Browser checkpoints/state imports are not accepted, so a stale client record cannot roll back public progress across worker or database restarts.
- Absolute visitor expiry is 24 hours. Revocation is serialized with actions. Expired/revoked sessions fail closed; confirmed missing sessions clear the cookie without converting a rejected action into a new case. Scheduled cleanup deletes expired/revoked visitors and cascades their heads; budget rows expire separately.
- Abuse limits persist in SQL: 2,000 requests/minute globally, 240/address/minute, 120/visitor/minute, 5 new visitors/address/minute, 60 new visitors/minute globally, and 10,000 active visitor capacity. Addresses are HMAC-hashed, not stored raw. These are configured limits, not measured capacity or bot-detection guarantees. Shared NATs can hit the conservative enrollment limit; review before launch and show Retry-After.

## Actual tests

Two public acceptance cases pass against a disposable real PostgreSQL cluster, Node HTTPS servers and Chromium, 0 skipped. They prove:

| Scenario | Actual result |
|---|---|
| Per-visitor isolation and wrong/missing CSRF | Foreign case 404; invalid CSRF 403; no foreign progress |
| Server-side grading/progression | Real HTTP completes all five missions and produces five Passport entries; invalid phase action refuses without advancing |
| Exact retry and concurrent revisions on two independent pools/service instances | Retry returns identical response; one competing edit succeeds, one gets 409 |
| Worker/service reconstruction and PostgreSQL process restart | Existing session/case/revision survives; no new empty head replaces it |
| Storage outage | 503; no memory fallback; the durable head remains available after recovery |
| Stale checkpoint/body import | 400; empty resume returns the current durable head |
| Revoke/action race, revoked/expired credentials | No mutation after revocation commit; later actions/reads refused; expired cookie cleared |
| Cleanup/lifecycle | Three expired/revoked test visitors removed; dependent heads cascade to zero |
| Same-site different-port browser request, cross-origin requests | Refused at request gate, with no CORS access |
| Request budget, unknown privilege fields, forwarding spoof | 413/400/429 as appropriate; spoofed client forwarding does not replace trusted socket IP in the test adapter |
| Least-privilege runtime DB role | All HTTP/browser operations run with SELECT/INSERT/UPDATE/DELETE only; CREATE TABLE is denied |
| Fresh visitor view and client artifacts | No training/record/checkpoint/fault/expected-answer fields; Secure HttpOnly cookie unreadable to JS; canary build scans 64 browser artifacts without credentials or private grading hints |

The fixture discovers PostgreSQL binaries via pg_config (or MICROFIRE_TEST_PG_BIN); it creates only a private disposable Unix-socket cluster and self-signed test HTTPS certificates, then removes them. TLS certificate checks are bypassed only for these test servers. The production pool always uses certificate verification. The tests do not establish the actual managed provider's TLS, backup, gateway or suspension behavior.

## Vercel/storage implementation and pending hosted acceptance

`createVercelPublicCampaignHandler` is a server-only, unmounted adapter. It requires VERCEL=1 plus explicit reviewed-protocol/enabled configuration, resolves the platform address through the official SDK, refuses missing/ambiguous platform context, lazily creates one shared pg pool and calls attachDatabasePool. It uses Node.js, not Edge. Per-pool max=2; connection/query/statement timeouts are bounded. No request body, cookie, proof, operator key or database URL is logged. Server failures are sanitized.

Production requires a managed TLS PostgreSQL pooler, a restricted runtime role, separately approved migration/cleanup, stable realm/epoch configuration across instances, a pinned HTTPS origin, verified Vercel gateway IP sanitization, provider connection/cost caps and network/WAF protections. Real hosted multi-instance, cold/suspended-worker, provider TLS, cleanup and firewall acceptance remain required before enabling anything. The application currently imports neither campaign factory from an API route; an actual production-build smoke test returns 404 for both namespaces.

PostgreSQL is the authoritative anti-rollback store; an administrative database restore to an older backup is outside this protocol guarantee. Anonymous cookie loss/24-hour expiry has no cross-device account recovery. Source/rules/epoch changes require an explicit migration/restart policy, never a silent scientific reassignment.
