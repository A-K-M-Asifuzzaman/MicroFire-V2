# Claim Trial — campaign contract

Implemented: APPRAISE_CLAIM evaluates the existing four authored statements with exact evidence selection, observed/derived/hypothesis/unknown classification, applicability, support versus contradiction/insufficiency and explicit flow-history/gravity/pressure confounders. Incorrect choices return source-linked reasons and remain correctable before completion. Completion requires all current appraisals plus the existing reducer criteria. Historical wrong choices remain in the accepted-event record and reducer correction history.

Compatibility correction for review: the unreleased Claim Trial thickness unit conversion now expects derived/analogous in the shared core as well as the campaign, matching the science ranking policy. Frozen M2 forbids classifications and is unaffected. Existing user answers are retained exactly; campaign correctness also checks evidence/support/confounders. This teaching correction requires independent science/consumer review before a mission UI is enabled. Completed evidence is read-only on revisit; a separate investigation retains a new revision history.

Contracts live in packages/shared/src/campaign.ts; deterministic authority in packages/game-core/src/campaign.ts; private authenticated adapter in apps/web/lib/campaign-service.ts. The new campaign format is version 1 / evidence-campaign-v1; it embeds the existing GameState v2, Passport v1 and unchanged M2 Training metadata. It does not alter the frozen bass-b20-training-v1 HTTP interface. No campaign HTTP route is installed; review of the new adapter/transport is required before wiring it to a frontend. The public registry stays unchanged.

Campaign records contain accepted, time-ordered actions. Replay derives objectives and all evidence, rather than trusting a saved completion boolean. The server adapter requires local operator authorization, scopes identities to runtime/session/revision, serializes competing commands, preflights/signs candidates and refuses live-head rollback. Revision is the accepted-event count. Snapshots are parsed with CampaignSnapshotSchema. Tests cover domain completion and server replay/restart; they do not establish mission UI availability.
