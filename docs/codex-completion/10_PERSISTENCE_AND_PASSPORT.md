# Persistence and Passport — safe review state

M2 retains the frozen signed checkpoint and shared pure admitLocalSave/admitLocalDiscard helpers. No writable browser adapter or feature flag is enabled. Existing normal/demo v1-key/v2-state migration remains separate from authenticated M2/campaign restore; unsigned legacy saves never become trusted training completion. Corrupt raw data stays exportable and explicit discard uses the existing confirmation/epoch/generation/tombstone rules. Existing training-save unit tests cover stale generations, newer heads, same-revision conflicts and raw-bound discard.

Campaign v1 adds replay-based persistence and a private CampaignService: start(request,sessionId), read(request,sessionId), command(request,CampaignCommand), resume(request,checkpoint), export(request,sessionId). Server methods require the authorized local request; no campaign HTTP endpoint is installed. CampaignIdentity binds rules/runtime/session/expectedRevision/action, permits finite decimal source conditions and sorts object keys with standard JSON number serialization. This is a new versioned identity; integer-only M2 canonicalJson/requestIdentity are unchanged. Shared CampaignRecordSchema, CampaignCommandSchema, CampaignSnapshotSchema and CampaignExportSchema describe the interface.

The server signs a realm/origin/key/catalog-bound accepted-event record using a distinct MAC domain. Restore verifies the signature/canonical bytes/strict shape, catalog/realm/key, timestamps and complete event replay. Derived source entries are lineage-validated. Revision conflicts cannot overwrite heads; exact accepted retries return the same checkpoint; start cannot reset an existing case. Restart needs a fresh grant/runtime. The exported educational record includes the signed checkpoint, replay events and validated Passport, preserving fictional scenario assumptions and learner explanations separately from NASA observations. Current and demo evidence are not mixed.

Local bounds: 8 campaign heads; 256 events and 128 KiB signed payload. Optional actions stop at 192 events or 96 KiB, preserving completion headroom. A regression completes all five missions after 191 mistaken reviews without deleting their history. This is a bounded local review campaign, not a public persistence architecture. Repeated useful edit cycles can still exhaust a finite record: preserve/export the case; do not reset or delete it automatically. Future public service requires reviewed compaction/durable identity/revocation/anti-rollback and transport/size/rate design. No public achievements or exactly-once recovery after process plus unsaved-response loss is promised.

Fresh native browser tests: Chromium 156.0.8078.4 passed 100 two-page serialized increments with zero lost updates, stale generation refusal and tombstone/reopen checks. Renderer/process isolation was not established, so this is not the required cross-process acceptance. WebKit 27.2 failed: 100 locked increments produced 86, a storage visibility/lost-update failure. Decision: all writable saves remain disabled. Native feature detection is insufficient. Checkpoint download and explicit server-validated resume remain the supported recovery path. Astra must independently verify engine/build/process isolation, crash/reopen, visibility, quotas/read-back and stale/case/tombstone interleavings before accepting any writable engine. No engine is certified by this run.
